Do this in order. Skip a layer and you will debug the wrong one.

## 1. Pick the GPU

- **32 GB local models:** [AMD Radeon AI PRO R9700](/gpus) (`gfx1201`). Official name — not an RX 9700.
- **16 GB is enough:** Radeon RX 9070 XT (also `gfx1201` on current matrices). Same generation, half the VRAM.
- **Already own a 7900 XTX:** still a practical home card (`gfx1100`). Different ROCm family package.

Read [Hardware](/hardware) before you buy a PSU or a toaster case.

## 2. Install ROCm on Linux

Practical Ubuntu path (as of the [weekly card](/)):

1. Use an Ubuntu LTS **named on AMD’s current matrix** (24.04.x is the usual home box).
2. Add **AMD’s Core SDK 10.0 repo** — or skip host ROCm and run an **official vLLM ROCm image** if serving is all you need.
3. Install **one** gfx family (`amdrocm-core-sdk10.0-gfx1201` on the R9700 — confirm with `apt-cache search`). Prefix is typically **`/opt/rocm/core-10.0`**.
4. **Do not** `apt install rocm` from Canonical’s archive. On new Ubuntu (including 26.04 reports) that has lagged at **7.1** and will not give you 10.0 or a current vLLM ROCm image.

Walkthrough: [Install ROCm](/tutorials/install-rocm). Prove it: [Verify GPU and ROCm](/tutorials/verify-rocm).

Before you rebuild the world: check **firmware / MES** after a kernel upgrade, and try **Vulkan llama.cpp** if HIP configure is a mess.

## 3. Pick inference software

Reliability path for Qwen on one R9700:

1. **llama.cpp** (HIP `gfx1201`, Vulkan if HIP is angry) — first tokens, first golden prompt.
2. **Ollama** — if you want a pull-and-chat wrapper and it actually attaches to the GPU.
3. **vLLM** — continuous batching, OpenAI server, spec decode. **Reliability this week:** ROCm 10 + AMD-validated **vLLM 0.27** (10.0 matrix, gfx1201 listed). **Community cutting-edge:** Docker **`vllm/vllm-openai-rocm:v0.30.0`** (previous try-tag `v0.29.0`). Those are different pins. Default `pip install vllm` is CUDA. Prefer llama.cpp HIP/Vulkan over official Ollama ROCm on gfx1201. Named Qwen model is being reworked.

Compare them on [AI software](/software). Run Qwen: [Local LLM tutorial](/tutorials/run-local-llm) then [Serve Qwen](/tutorials/serve-qwen).

If you also run the Ubuntu **[Radeon Stack Lab](/stack-lab)** companion (Origin repo / local app), treat **`qwen-reliable`** as a slot being reworked. There is no `qwen3-8b-try` profile on this pass.

## 4. Optional harness

A **harness** is the agent loop *above* the model: tools, memory, chat apps. It does not replace ROCm.

- **[Hermes Agent](https://hermes-agent.nousresearch.com/)** (Nous Research) — local llama.cpp runtime (Vulkan on AMD unless you point at your own server) or any OpenAI-compatible endpoint.
- **[OpenClaw](https://docs.openclaw.ai/)** — self-hosted gateway into Discord/Telegram/etc., with Ollama, vLLM, and llama.cpp providers.

Details: [Harnesses](/harnesses). `curl` `/v1` first. Then point the harness at `127.0.0.1`. Local Hermes can also draft the [weekday YAML scrape](/maintain) overnight — a human still commits.

## Stop conditions

- `rocminfo` has no `gfx1201` → do not download 20 GB.
- `rocm-smi` idle while you “generate” → you are on CPU.
- Harness is slow → check the **backend**, not the card’s reputation.
