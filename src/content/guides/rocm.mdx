**ROCm** is AMD’s GPU compute stack: kernel driver plus versioned userspace (HIP, `rocminfo`, `rocm-smi`, math libraries) plus **framework wheels that must match**. On the Radeon AI PRO R9700 the ISA name is **`gfx1201`**.

It is no longer fair to say “ROCm doesn’t work” for **single-GPU** local LLM inference on Ubuntu. It is still fair to say **it is not CUDA**, and the **packaging/version mess** is the pain.

<Callout type="linux">
Linux is the real platform. Windows can do Vulkan inference and a thin PyTorch slice. Home labs that want HIP and server tools should plan on a listed Ubuntu (or other matrix) install.
</Callout>

## Two streams, one trap

Since **7.14**, production ROCm is built on **TheRock**. **Core SDK 10.0.0** (AMD notes: 26 Aug 2026) is the current production line as of our [weekly snapshot](/). **7.14.1** (early Sep 2026) is the previous patch line — a valid pin, not “the new 10.0.”

**Canonical / Ubuntu archive** packages (people have seen **7.1**-era `apt install rocm` on new Ubuntu) are a **third** story. They will not give you 10.0, `amdrocm-*` prefixes, or a vLLM 0.29 extras wheel that expects a modern userspace.

<Callout type="warn">
If you care about ROCm 10.0 or current vLLM ROCm builds, **do not** treat archive `apt install rocm` as the install. Add AMD’s 10.0 repo (or use their container/runfile) as the [install tutorial](/tutorials/install-rocm) describes.
</Callout>

## TheRock packaging you will actually type

Official 10.0 transition notes:

- Packages are named **`amdrocm-*`** so they do not collide with leftover `rocm` packages.
- Install prefix is **scoped** (docs mention `/opt/rocm/core` style trees; expect something like **`/opt/rocm/core-10.0`** — confirm with `ls /opt/rocm`).
- Install **one GPU family**, not the kitchen sink:
  - all-GPU: `amdrocm-core-sdk10.0`
  - RDNA3-style: suffix like `-gfx110x`
  - RDNA4 / RX 9000 / **Radeon AI PRO R9700**: gfx1200/gfx1201 family (docs list a combined `-gfx1200-gfx1201` suffix; some notes say `-gfx1201`). **`apt-cache search amdrocm-core-sdk10.0`** on the day you install.

R9700 is **first-class** on the 10.0 device table (`gfx1201`), same row as RX 9070 / 9070 XT.

## Framework pins vs “what people run”

AMD’s **10.0.0 release notes** listed, among others:

- PyTorch **2.13.0**
- vLLM **0.27** (explicitly including gfx1200/gfx1201)
- SGLang **0.5.15**

That is the **AMD-supported combo**. Upstream vLLM has already moved (0.29 ROCm extras, 0.30rc in the wild). The home card tells you which pair we would try **this week**. These [version notes](#version-notes) stay as history.

## Mental model

1. **`amdgpu` kernel module** — one source. Mixing DKMS + distro + a leftover runfile is a black screen.
2. **ROCm userspace** — the `amdrocm` / `/opt/rocm` tree.
3. **Wheels / containers** — PyTorch, vLLM, TGI. They ship their own ROCm-flavored builds.

Containers do not replace a host KFD that the image understands.
