Goal: **official Qwen instruct** generating on the R9700, with `rocm-smi` showing GPU use. llama.cpp first (you control the backend). Ollama is optional and still rocky on this card. vLLM is the [next tutorial](/tutorials/serve-qwen).

<Callout type="check">
**Default:** being reworked — no named 7B or 8B card. Smoke-test on a small **official** GGUF, then stay on official instruct. Do not start with 70B or an [abliterated](/abliterated) file.
</Callout>

## Do this in order

1. [ROCm installed](/tutorials/install-rocm) and [verified](/tutorials/verify-rocm)
2. Build llama.cpp (HIP, or Vulkan if HIP is messy)
3. Run one official instruct GGUF with `-ngl 99`
4. Confirm `rocm-smi` moves
5. Optionally expose `llama-server` on `127.0.0.1:8080` — then [attach a harness](/harnesses)

```bash
sudo apt install -y build-essential cmake git
```

Fedora/RHEL: same idea, different package names.

## Path A — HIP (ROCm)

```bash
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
cmake -B build \
  -DGGML_HIP=ON \
  -DAMDGPU_TARGETS=gfx1201 \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

CMake names moved (`GGML_HIP` now; older posts say `LLAMA_HIPBLAS`). If configure fails, read the repo’s HIP docs for the commit you cloned.

```bash
export HIP_PATH=/opt/rocm
export PATH="/opt/rocm/bin:$PATH"
./build/bin/llama-cli --list-devices
```

You want the Radeon AI PRO R9700, not only an iGPU.

### Official GGUF

Trust the card (Hugging Face official or a known GGUF publisher). This site does not pin a filename that will rot next month.

```bash
mkdir -p ~/models
# huggingface-cli download … the official instruct GGUF you chose
```

### Run all layers on the GPU

```bash
./build/bin/llama-cli \
  -m ~/models/YOUR-OFFICIAL-QWEN.gguf \
  -ngl 99 \
  -c 4096 \
  -p "Say hello from a Radeon AI PRO R9700." \
  -n 64
```

`-ngl 99` means “offload what fits.” On 32 GB with a 7B–8B quant, that should be everything.

```bash
watch -n1 rocm-smi
```

VRAM should rise. If it stays empty, you are on CPU — stop.

### llama-server (`/v1`)

```bash
./build/bin/llama-server \
  -m ~/models/YOUR-OFFICIAL-QWEN.gguf \
  -ngl 99 \
  --host 127.0.0.1 \
  --port 8080
```

Clients use `http://127.0.0.1:8080/v1`. Do not bind `0.0.0.0` unless you mean to.

## Path B — Vulkan (fallback)

If HIP configure is a mess and you still want tokens tonight:

```bash
sudo apt install -y libvulkan-dev
cmake -B build-vk -DGGML_VULKAN=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-vk -j"$(nproc)"
./build-vk/bin/llama-cli --list-devices
```

Pick the **RADV GFX1201** (or AMDVLK) device that is the R9700, not the iGPU. Set `GGML_VK_VISIBLE_DEVICES` / `VK_ICD_FILENAMES` only after `--list-devices` shows the confusion.

Vulkan is a real backend, not a consolation prize.

## Path C — Ollama (optional)

Official Ollama ROCm is **still rocky on R9700**. Install from [Ollama’s Linux page](https://ollama.com/download/linux) only if you want the wrapper.

```bash
ollama --version
ollama run <a-small-official-tag>
rocm-smi
ollama ps
```

If VRAM never moves, go back to llama.cpp. Do not set random `HSA_OVERRIDE_*` on a card current ROCm already lists.

## What “it works” looks like

- Tokens stream at interactive speed for a 7B–8B quant (you will know CPU)
- `rocm-smi` VRAM is roughly the file plus cache
- A second prompt still works

Then: raise `-c`, or [serve `/v1`](/tutorials/serve-qwen) for a harness. Compare HIP vs Vulkan on the **same** GGUF if you like — notes, not leaderboards. Abliterated weights come *after* this pipe is boring.
