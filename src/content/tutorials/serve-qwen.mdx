## Path A — llama-server (least pain)

You already built llama.cpp in [Run a local Qwen](/tutorials/run-local-llm). Use an **official** instruct GGUF (Q4_K_M or Q5_K_M on 32 GB — confirm the card’s file size).

```bash
./build/bin/llama-server \
  -m ~/models/YOUR-OFFICIAL-QWEN.gguf \
  -ngl 99 \
  --jinja \
  --host 127.0.0.1 \
  --port 8080
```

`--jinja` matters on current Qwen templates.

```bash
watch -n1 rocm-smi
curl -s http://127.0.0.1:8080/v1/models
curl -s http://127.0.0.1:8080/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen","messages":[{"role":"user","content":"Reply with the single word READY and nothing else."}],"max_tokens":8}'
```

If VRAM never moves, stop. Point Hermes or OpenClaw at `http://127.0.0.1:8080/v1` **only after** this returns `READY`.

## Path B — vLLM (when you need a real server)

Two pins. Do not mix them in one venv. The [weekly card](/) is the current recommendation.

**Reliability (`qwen-reliable`) — AMD-aligned vLLM 0.27 / ROCm 10**

Serve [Qwen/Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct) BF16. Copy the current image tag from [AMD’s vLLM page](https://rocm.docs.amd.com/projects/ai-ecosystem/en/latest/inference/vllm.html) (docs snapshot: vLLM **0.27** + PyTorch **2.13**).

**Cutting-edge try (`qwen3-8b-try`) — vLLM 0.29 ROCm extras**

Uncertain on R9700. For [Qwen/Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B) only after 0.27 works.

```bash
# ROCm extras — NOT default PyPI
pip install vllm --extra-index-url https://wheels.vllm.ai/rocm/0.29.0/rocm723
# or
docker pull vllm/vllm-openai-rocm:v0.29.0
```

```bash
# Image tags change. Confirm against AMD or vLLM docs.
docker run --rm -it \
  --device /dev/kfd --device /dev/dri \
  --group-add video --ipc=host --network host \
  -v "$HOME/models:/models" \
  vllm/vllm-openai-rocm:v0.29.0 \
  --model /models/YOUR-QWEN-HF \
  --host 127.0.0.1 --port 8000
```

<Callout type="warn">
`pip install vllm` with no extra index is **CUDA**. If import looks NVIDIA-shaped, you installed the wrong wheel.
</Callout>

```bash
curl -s http://127.0.0.1:8000/v1/models
```

OpenClaw’s vLLM provider wants `http://127.0.0.1:8000/v1` and `VLLM_API_KEY` set (dummy is fine if the server does not auth).

## Golden checks

1. Short `READY` completion.
2. A second turn that stays in-template.
3. `rocm-smi` during both.
4. Then: harness tools. Then, if you still want it, a second weight (coder / Qwen3-8B try / abliterated).

If thinking never ends, stay on official instruct with thinking off, or fix `--jinja`. Do not “fix” it by grabbing a random uncensored GGUF.
